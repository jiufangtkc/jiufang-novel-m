# WO-66 自動點擊測試（入口檢查）說明文件

本目錄為工單 **WO-66** 所建立之自動點擊測試套件，負責在四種版面下逐項走訪各項介面入口，驗證「看得到、按得下去、走到對的頁面，且能順利返回」。

總覽、Playwright 設定與產出位置請見上層 [`qa/README.md`](../README.md)。

---

## 1. 執行環境與預先需求

- **Node.js**：ESM 模組環境。
- **Playwright**：不是專案依賴。請設定 `PLAYWRIGHT_MODULE`（與倉庫 `scripts/` 目錄既有腳本相同），指向本機 playwright 套件。
- **瀏覽器**：
  - 預設：手機直拿、手機橫拿、中等使用 WebKit；寬版使用 Chromium。
  - 若 WebKit 未裝妥，可設 `ENGINE=chromium`，改以 Chromium 代測（視窗、觸控與斷言不變）。報告會註明沒有 WebKit 證據。
  - 若 Chromium 執行檔不在 Playwright 預設位置，請再設 `CHROMIUM_PATH`。

---

## 2. 如何執行

### 主檔路徑

- `qa/入口檢查/run.mjs`

### 對準本機預覽（預設）

```bash
BASE=http://127.0.0.1:4173 ENGINE=chromium node qa/入口檢查/run.mjs
```

未設 `BASE` 時，預設也是 `http://127.0.0.1:4173`。若要測已部署的第 3 階段分支預覽：

```bash
BASE=https://stage3-cards.jiufang-novel-m.pages.dev ENGINE=chromium node qa/入口檢查/run.mjs
```

### 環境變數

- `ENGINE=chromium`：原本用 WebKit 的直拿、橫拿、中等改用 Chromium 代測；並沿用 WO-67 的瀏覽器能力模擬（移除 Chromium 才有的檔案存取視窗 API，讓 App 走與 iPhone／iPad Safari 相同的路徑；系統存檔／選檔視窗因此未測）。
- `QA_DIR`：截圖、`結果-第X次.json／.md`、最新 `結果.json／.md` 的輸出資料夾。未設時寫入 `test-results/qa/入口檢查/`。
- `WO66_DIR`：`測試結果-第X次.txt` 與 `WO-66-測試結果-第X次.md` 的輸出資料夾。未設時與 `QA_DIR` 相同。
- `RUN_INDEX`：手動指定第幾次。未設時依產出目錄既有報告自動往下編號。

```bash
RUN_INDEX=1 QA_DIR=test-results/qa/入口檢查 node qa/入口檢查/run.mjs
```

腳本只檢查「開啟稿子」按鈕與檔案選取輸入框是否存在，**不會選取任何真實書稿或本機 `.db`**。第 1 節開新稿時，書名固定為「【範例】自動測試稿」。

## 3. 四種版面定義

| 版面名稱 | 視窗尺寸 (寬×高) | 觸控支援 | 模擬裝置 / 瀏覽器引擎 | 導覽模式 |
|---|---|---|---|---|
| **手機直拿** | 390 × 844 | 啟用觸控 (`hasTouch: true`) | iPhone 13 (WebKit) | 底部分頁導覽列 (`bottom-nav`) |
| **手機橫拿** | 844 × 390 | 啟用觸控 (`hasTouch: true`) | iPhone 13 landscape (WebKit) | 浮動按鈕與抽屜選單；目錄抽屜左邊直排分頁 (`nav-rail`，WO-68) |

## 4. 四種版面執行步驟

每個版面啟動獨立的瀏覽器 Context，依序執行以下 8 個章節檢查：

### 第 1 節：首頁
1. **開啟稿子入口**：驗證「開啟稿子」按鈕與檔案選取 input 存在（未選取任何真實 `.db` 檔）。
2. **最近清單打開稿子**：從最近清單點選「【範例】霧港紀事」，驗證可順利開啟並進入寫作頁。
3. **基本設定畫面入口**：驗證可進入稿件設定基本畫面並能返回。
4. **開新稿子**：填寫書名「【範例】自動測試稿」建立新稿，確認順利進入寫作頁。
5. **新稿今日字數與寫作紀錄**（WO-69 起必須通過）：建立後用畫面分頁走到統計（橫拿先按「展開目錄」再點直排分頁），確認今天寫了、連續、最長連續、近七日、時數、有寫天數、已達成次數都是 0，且沒有 10/18～10/28 範例日期；再用分頁回寫作。不跳內部網址；不符即記失敗。

### 第 2 節：五個分頁
檢查寫作、資料集、檔案、統計、設定五個分頁：
- **手機直拿、中等**：檢查底部分頁（`bottom-nav`）五個按鈕皆看得到、按得下去、能走到相應分頁並順利返回寫作頁。
- **寬版**：檢查左側導覽列（`nav-rail`）五個按鈕正常切換與返回。
- **手機橫拿**（WO-68 起必須通過）：目錄抽屜左邊的直排分頁（`nav-rail`）。檢查目錄頁五分頁順序、44×44 以上、不叫出底部分頁、不壓目錄；逐一進入再用「寫作」返回；已進章的寫作頁未展開目錄時不顯示分頁，按「展開目錄」後出現分頁且正文讓位；「收合目錄」後可再打開；寫作頁經分頁走到檔案再返回；從「今天還沒另存」進檔案頁也回得來（死路檢查）。找不到、按不下去或回不來一律記失敗。

### 第 3 節：寫作頁
1. **換章打字**：切換至指定章節，於正文編輯區輸入測試文字並驗證更新。
2. **打字時底部分頁收起**：驗證鍵盤彈起時底部分頁是否收起（直拿依清單四標記為 WO-78 待修）。
3. **目錄開關與返回**：驗證直拿返回目錄、橫拿左側浮動按鈕開關、中等頁首按鈕開關、寬版常駐目錄。
4. **直拿下方目錄按鈕**：直拿頁尾目錄按鈕檢查（直拿依清單四標記為 WO-80 待修）。
5. **看卡片開關與打字接續**：點擊「看卡片」按鈕展開卡片面板，再關閉卡片，驗證正文編輯區仍可正常接續輸入。
6. **專注模式進出**：進入專注模式（橫拿浮動按鈕，直拿/中等頁尾拇指區按鈕，寬版按鈕），驗證隱藏周邊元素；點擊離開按鈕（或橫拿點兩下）回到標準寫作頁。
7. **今日寫了與每日目標顯示**：驗證頂部或狀態欄顯示字數統計與進度。
8. **暫存與另存狀態顯示**：驗證「已暫存」或存檔狀態文字正常顯示。

### 第 4 節：目錄
1. **點章或幕進入寫作**：點選目錄樹中之章節項目，驗證順利導航至寫作頁。
2. **章節更多操作選單（⋯）**：點擊章節右側「⋯」叫出選單，驗證選單展開並可點擊空白處關閉（中等與橫拿因抽屜遮蔽標記為 WO-70 待修）。
3. **新增章入口**：驗證目錄底部「新增章」按鈕（直拿已實作；橫拿、中等、寬版依清單四標記為 WO-71 待修）。
4. **整理目錄入口**：直拿進入整理目錄模式並完成返回；寬版支援拖曳排序。
5. **改書名入口**：點擊頂部書名，驗證改書名對話框彈出並可取消返回。
6. **進度標記入口**：點擊進度標籤，驗證進度狀態選單彈出並可關閉。

### 第 5 節：資料集
1. **分類清單進出**：切換至資料集分頁，驗證角色、世界觀、道具等分類清單顯示。
2. **開啟分類與卡片檢視**：點入分類檢視卡片列表與預覽。
3. **編輯卡片與取消**：驗證卡片編輯介面與取消功能。
4. **最近刪除與復原入口**：驗證「最近刪除」清單入口可進出。
5. **整理分類入口**：驗證「整理分類」介面可進出，內建分類受到保護。
6. **新增卡片與子卡片**：驗證資料集新增按鈕（目前四種版面皆未實作，依清單四標記為 WO-73 待修）。

### 第 6 節：檔案頁
1. **另存專案入口**：驗證「另存專案」按鈕看得到且功能正常（寬版額外驗證「儲存專案」）。
2. **立刻暫存稿子**：點擊「立刻暫存稿子」，驗證暫存回饋訊息。
3. **匯入匯出準備中狀態**：點擊「匯入文字檔」與「匯出全文」，驗證具備 `aria-disabled="true"` 與明確「準備中」提示。
4. **檔案頁最後一項邊界**：直拿與中等驗證頁底項目未被底部分頁遮蔽。
5. **關閉稿子回首頁**：點選「關閉稿子並回首頁」，驗證可順利返回首頁。

### 第 7 節：統計與設定
1. **統計頁與過程紀錄**：切換至統計分頁，點擊「查看寫作過程紀錄」驗證可進入日誌並返回。
2. **寫作目標對話框**：點擊每日目標設定，驗證目標對話框彈出並可取消。
3. **設定頁寫作過程紀錄入口**：切換至設定分頁，驗證其寫作過程紀錄入口正常可見與進出。
4. **字型授權入口與返回**：點擊芫荽字型授權連結（目前直接導向純文字檔無返回按鈕，依清單四標記為 WO-85 待修）。

### 三、舊功能不可弄壞檢查
1. **檔案頁三組標題**：確認「存檔」、「開啟與關閉」、「匯入與匯出」三組標題皆完整存在。
2. **禁用分類名檢查**：嚴格檢查頁面不得出現已禁用的「場景」分類，且手機版不得出現「AI 對話紀錄」分類。
3. **全站用詞繁體與規範檢查**：全站文字必須符合臺灣繁體中文與用詞，不得出現簡體字或禁用語彙（如假資料、示範等）。

## 5. 輸出檔案與報告格式

每一次測試執行完成後，自動產出下列檔案（預設都在 `test-results/qa/入口檢查/`，不會進倉庫）：
- `結果-第X次.json`：完整結構化測試數據（含版面、大項、項目、狀態、工單、說明、截圖）。
- `結果-第X次.md`：Markdown 格式總覽表格。
- `WO-66-測試結果-第X次.md`：同一份 Markdown 報告的工單留存檔名。
- `測試結果-第X次.txt`：終端機完整執行日誌。
- `shot_*.png`：待修或失敗項目之佐證截圖。

## WO-69 修改（2026-11-14）

- 第 1 節「新稿今日字數與寫作紀錄」由「待修後必須通過（WO-69）」改為必須通過，並改用畫面分頁往返（原本用跳網址進統計、再跳網址回寫作）。
- 依 WO-69 工單，正式執行不再使用 force 點擊：畫面清理與各節收尾的 `click({ force: true })` 改為一般點擊（逾時 3 秒，失敗照舊略過、不影響判定）；檔案頁「匯入文字檔」「匯出全文」是 `aria-disabled` 的準備中按鈕，改以真實指標點擊按鈕中心點（觸控 tap、滑鼠 click），會照實受遮擋判斷。
