# 九方小說編輯器M：階段 0 與階段 1 樣品

這一份是給九方看的。不用會寫程式也能看懂。

## 這次做了什麼

倉庫裡現在有一個網頁版的樣品，名字是「九方小說編輯器M」。

- 打開是暗色畫面，顏色、圓角、底部四個按鈕（寫作、資料集、統計、設定）照現有手機 App。
- 字用芫荽。字型檔切成很多小塊，畫面上用到哪些字，瀏覽器才下載哪些。授權聲明放在網站裡。
- 可以加到 iPhone 主畫面。名稱是「九方小說編輯器M」，圖示是深色底、藍色書本。
- 首頁、章節目錄、寫作畫面都能點。寫作區是手機自己的文字框，**可以真的打字**。
- 寫作畫面底下有一條今日目標進度條，標的是「今日已寫」和「目標」。另一行才是「本章字數」，兩個數字不會混在一起。還沒達標是藍色，慢慢變長；達標時變成綠色，安靜地發一點光，不閃、不蓋住正文。
- 統計頁有「已達成幾次」。這個次數只算已經結束的日子，今天就算亮著也不先算進去。
- 設定裡可以改每日目標（最少 300 字，沒有上限），也可以選一天幾點結束，預設午夜 12 點。
- 另有一頁「寫作過程紀錄」，一天一列，有字數、寫作時間、大量貼上、大量刪除。
- 所有書名、章節、統計數字都是假的，標題或內文裡看得到「示範」或「示範假資料」。沒有放真實書稿。
- 沒有 AI。統計頁沒有「AI 助手介入度」。
- 還沒有做匯入電腦版 `.db`。首頁的「開啟檔案」會說明這件事，不會讀任何檔案。
- App 本身的授權條款（LICENSE）還沒放，因為九方還沒決定。芫荽字型自己的授權有附上，那是字型規定必須附的，不是 App 的條款。

進度條和「一天結束怎麼算」的規則，已經寫成程式裡的純計算，並用 48 個自動測試蓋過這些情況：跨過午夜、把結束時刻改成清晨 4 點、同一天把目標調高又調低、亮過又熄、匯入舊紀錄時用當時的目標一次算完就鎖住。畫面目前接的是假資料，所以九方現在看到的次數不會跟著改系統日期重算過去。

## Cloudflare Pages 要怎麼接

等這個合併請求合進 `main` 之後，用九方的 Cloudflare 帳號把 Pages 接到這個 GitHub 倉庫。請填：

- **建置指令**：`npm run build`

## 請用真的 iPhone 試才知道的事

這個樣品在電腦上的 WebKit 裡點過、打過字、試過貼上。下面這些和真的 iPhone 不一定一樣，請九方用自己的手機確認：

1. **注音、倉頡**。組字還沒選字時，程式不去改文字框。選字按 Enter，不該多出一行，也不該觸發存檔。電腦上的 WebKit 沒有注音鍵盤，這段只能在 iPhone 上試。
2. **鍵盤會不會擋住正在打的那一行**。程式有跟著鍵盤把畫面縮短、把游標捲上來，但是 iPhone 的鍵盤行為要實機看。
3. **加到主畫面**。圖示和名稱「九方小說編輯器M」是否正確，名稱會不會被系統截斷。
4. **沒有網路時打不打得開**。電腦上的 WebKit 已經用「把網站伺服器關掉」測過：第一次打開並等它存好之後，重新載入首頁和寫作畫面都還在，可以打字，字仍是芫荽。請九方再用自己的 iPhone 開飛航模式確認一次。
5. **從主畫面圖示打開，和從 Safari 分頁打開，資料會不會變成兩份**。如果會，以後的說明要提醒固定從圖示進去。
6. **複製、分享、拖曳**。見下一節。
7. 字看起來是不是芫荽。芫荽只有一種粗細，標題的「粗」是瀏覽器幫上去的，筆畫可能和舊 App 的粗黑體不完全一樣。

## 複製貼上：擋得住的，和擋不住的

寫作區的目標是：正文不要貼到別的 App，別的 App 的文字也不要貼進來；在這個編輯器裡複製的，可以再貼回這個編輯器。

在這次的 WebKit 裡試過：

- 從外面貼進來的句子進不去，畫面會說「外面的文字不能貼進來」。
- 在編輯器裡複製時，系統剪貼簿放的是一段看不見的標記，不是正文。再用貼上，編輯器會把剛才那一段貼回來。
- 把文字拖進文字框會被擋下。

**沒辦法保證、也不該假裝擋得住的：**

- 看著螢幕自己打一遍，或用另一支手機看。
- 語音輸入。那是打字，不是貼上，不能擋，否則注音和語音都不能用。若一次落下很多字，會記在「大量文字」裡，供之後查看，但不會把字刪掉。
- 截圖、螢幕錄影、拍照。
- iPhone 的輔助使用（例如朗讀選取的字）。
- 電腦上的開發者工具。
- 選取氣泡裡的「拷貝」、分享、或用手指把選取的字拖到別的 App。若 iPhone 沒把這個動作交給網頁，或不理會「取消複製」，正文仍可能進剪貼簿。**這必須用九方的 iPhone 試。** 程式能做的，是在網頁收得到的複製動作裡，不要把正文放進系統剪貼簿。
- 網頁程式還沒載入完成的那一瞬間。
- 組字還沒選完字時不去改文字框，所以這時候的貼上會先略過，選完字再貼。

先前已經跟九方說過：沒有辦法百分之百保證是純人工打的。這份樣品也一樣。

## 我自己定的、九方可以改的

- **字數**：去掉空白之後，一個字（含標點）算一個。和電腦版是否完全相同，等有測試用的 `.db` 再對。
- **停筆**：打字停下來約 0.6 秒，才更新字數、今日目標和「已記下」。組字過程中不算、也不存。
- **大量文字**：一次出現或刪掉 50 個字以上才記一次。注音、倉頡送出一個詞不算。50 這個門檻可以改。
- **一天幾點結束**：進行中的這一天仍走到原來的時間才結算。新的時間從下一個寫作日才用。已經結算的日子完全不重算。若新時間會指回剛結算的那一天，不把那一天打開，改從下一個還沒用過的日期繼續，避免同一天算兩次。
- **達標次數**：只在那天結束時，用最後一次設定的目標比對當天字數。中途亮過又熄，結束時沒達標，就是 0，不算 1。一天最多 1 次。今天的光只是即時提示。
- **新的一天**：一開始用前一天最後設定的目標。
- **匯入舊紀錄**（函式已經寫好，畫面還沒接檔案）：用匯入當下的每日目標，把過去每一天算一次，算完就固定。同一天若有兩列，留最後一列，仍然只算一天。
- **寫作紀錄的欄位**和電腦版對齊，包含 AI 相關欄位，但畫面不顯示那些數字，交回時才不會把電腦版已有的紀錄弄丟。
- **資料集**這階段只有說明，沒有卡片。
- 寬螢幕（例如平板）會變成左邊直排按鈕、目錄和寫作並排。這次截圖是手機尺寸。

## 離線為什麼上次會失敗

上次用測試工具的「模擬斷線」。這個環境的 WebKit 只要一切斷線，連一個沒有離線程式的空白頁也會內部錯誤，所以當時讀不到頁面，不代表快取壞了。

這次改成把預覽伺服器真正關掉（連線被拒絕，和飛航模式一樣是真的連不上）。結果是：第一次打開、等服務程式把畫面和芫荽存好之後，重新載入首頁與寫作畫面都開得了，可以打一個字，正文仍用芫荽。

另外補了一件事：字型小塊改成第一次打開時就存進手機。先前字型常常在離線程式接手之前就下載完，沒有放進離線快取；若只靠當時的記憶，換一頁或重新載入後，冷門的字可能變回系統字。
